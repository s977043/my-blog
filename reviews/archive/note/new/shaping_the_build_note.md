## 指摘コメント

### 該当箇所 1（🔴 公開ブロッカー・修正済み）

L58-L66（Shaping の 7 観点）

```
| 観点 | 問い |
| --- | --- |
| Problem | 本当に解くべき問題は何か |
...
| Stop | どの条件なら止めるのか |
```

#### 問題点

**note の WXR インポートは Markdown テーブルを描画できず、取り込み時にセルがプレーンな行へ平坦化される**（AGENT_LEARNINGS 2026-05-15 / PR #244 で `n5fe2e97b9600.md` の表崩れを実際に踏んでいる）。この表は「7 つの問いへ分解する」という記事の骨格そのもので、直後に同じ 7 項目を太字で詳述する導入としても機能しているため、崩れると読解が明確に落ちる。`npm run check:note-tables` が WARN を検出した唯一の箇所。

WARN は非ブロッキング設定だが、**公開後に気づいて手戻りした前科がある**項目のため公開前に解消すべきと判断した。

#### 提案

直後の詳述パート（`**Problem**` 形式）と表記を揃えた箇条書きへ変換する。画像化も選択肢だが、`articles_note/assets/` 配置 → main 先行マージ → `--base-url` 付き WXR 生成という手順が増えるため、この内容量では箇条書きが適切。

```
- **Problem**: 本当に解くべき問題は何か
- **Evidence**: その問題が存在する証拠はあるか
...
- **Stop**: どの条件なら止めるのか
```

**対応**: 反映済み（`check:note-tables` の本記事に対する WARN 解消を確認）。

### 該当箇所 2（🟡 修正済み）

参考セクション

```
- Andrew Ngによる紹介投稿
  - https://x.com/AndrewYNg/status/2088302050706686198
```

#### 問題点

`curl` は 200 を返すが、**X は SPA のため存在しない ID でも 200 を返す**ので、この確認は実在の証拠にならない。参考文献として実在検証できない URL を残すのは、一次情報の正確性を売りにする本記事の構成と噛み合わない。

#### 提案

issue-366 を実取得して確認したところ、X 投稿の参照先はこの号そのもので、**Skills Map の専用ページは存在しない**（本文に「より詳細な Skills Map を共有し、今後数通のレターで詳述する予定」との記載があるのみ）。したがって置き換え先がなく、参考リスト 1 件目の issue-366 と重複するため、項目ごと削除するのが正しい。

**対応**: 削除済み。参考は検証済みの issue-366 と前記事の 2 件構成となった。

## 良い点（維持すべき）

- **反論の正面処理**: 「昔から Product Discovery や要件定義でやってきたことではないか」という、この主題で最も強い反論に専用セクションを充て、「変わったのは重要度と反復速度」と着地させている。シニア読者からの離脱を防ぐ設計として有効。
- **役割侵食の明示的否認**: 「エンジニアが PdM になる話ではない」「PdM・デザイナー・エンジニアの責任を曖昧にすることでもない」を明記。PdM 読者に最も燃えやすい誤読を先回りして潰せている。
- **「作らない判断」の組み込み**: Evidence 不足なら AI 回答機能ではなく計測・調査を先に作る、という例が Shaping を単なる企画力から区別する具体になっている。抽象論に留まらない一番効いている箇所。
- **前記事との接続構造**: Skills Map（Human Capability）と前記事の設計対象（Design Target）を「別の軸の地図」として重ねる整理が、続編としての存在理由を成立させている。
- **用語の慎重な扱い**: `Time to Learning` を一般用語として断定せず「ここでは便宜上」と定義しており、造語を既成概念のように見せる罠を避けている。
