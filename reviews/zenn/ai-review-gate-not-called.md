### ChatGPTレビューで追加修正したCritical 2件

#### 1. Skillの `allowed-tools` を排他的な権限制限だと解釈していた

旧稿では次の設定を「Edit / Write / Bash を持たせない」仕組みとして説明していました。

```yaml
allowed-tools:
  - Read
  - Grep
  - Glob
```

Claude Code公式ドキュメントを確認すると、Skillの `allowed-tools` は列挙ツールを**事前承認する**設定であり、利用可能なツールを排他的に制限するものではありません。

- https://code.claude.com/docs/en/skills#pre-approve-tools-for-a-skill

排他的にツールを制限する用途では、Custom Subagentの `tools` allowlistなどが利用できます。

- https://code.claude.com/docs/en/subagents#available-tools

**対応**:

- 「権限による強制」という説明を削除
- `allowed-tools` の誤認自体を記事の失敗事例として追加
- 次の改善項目に「実効的なread-only境界の実装・テスト」を追加

#### 2. 「成果物がない」ことから「未実行」を推論していた

旧稿では、レビュー成果物を確認できた記事が8本中2本だったことから、残り6本を「ゲートが呼ばれなかった」と扱っていました。

しかし、記事自身がRecord工程の失敗を扱っている以上、成果物がないことは未実行の十分条件ではありません。

**対応**:

- タイトルを「品質ゲートは効かなかったのではなく、『呼ばれたか』を測れていなかった」へ変更
- 指標名を「実行証跡カバレッジ25%」へ変更
- 6本のうち未実行を別記録で確認できた1本だけを確定事実として記載
- 残り5本は実行有無を断定しない
- ファネルを「真の実行件数」ではなく「観測できた件数」と明記

## 更新稿のレビュー

### 1. 事実精度

**判定: PASS**

「観測できないものを0として数える」推論はありません。

現在は次を明確に分けています。

- 母集団: 変更した記事8本
- 確認できたもの: Humanizeの実行証跡2本
- 確認できないもの: 残り6本の実行有無
- 別記録から確定できるもの: 少なくとも1本はHumanize工程を迂回

旧稿の「3件を失った」も、「現在の成果物には残らずGit履歴からのみ追跡できる」へ修正済みで、物理的消失と現在状態からの再現不能を分離しています。

### 2. 技術的正確性

**判定: PASS**

Claude CodeのSkillとCustom Subagentのツール制御を公式仕様に合わせています。

記事は、Skillの `allowed-tools` だけではread-only境界を保証できないことを明記しています。これは「設定が存在することと、制約が実効していることは別」という中心的な教訓とも整合しています。

### 3. 論理構成

**判定: PASS**

更新稿は次の順序です。

1. 検出ロジックで何が動いたか
2. 権限制約の誤認
3. 非ブロッキングと `unverified` の分離
4. 何が実測できたか
5. 何が観測不能だったか
6. なぜ気づけなかったか
7. 次にどう観測可能にするか

「検出は動いた」と「ゲート全体が機能した」を分離したことで、冒頭と結論の整合性も上がりました。

### 4. 状態設計

**判定: PASS**

Mermaidでは、正常系を次の順序で表します。

```text
eligible
  → started
  → result_received
  → persisted
  → validated
  → decided
  → verified
```

異常・未完了状態は `unobserved` / `failed` / `unverified` として別に残します。

特に `eligible` をHumanizeの外側で生成するため、ゲート自身が未起動でも分母を失いません。

### 5. 実務価値

**判定: PASS**

改善案で最も重要なのは、`eligible` をHumanizeの外側で生成する点です。

ゲート自身が起動時にレコードを作る設計では、未起動を観測できません。対象記事の変更検出側が最初のレコードを生成することで、`started_at: null` を意味のある状態として扱えます。

これはHumanize固有ではなく、AIレビュー・セキュリティスキャン・承認フロー・QA・Verifierにも適用できます。

### 6. 読みやすさ

**判定: PASS**

Mermaidは1枚に限定され、本文の「観測できた件数」から「次に作る状態」への橋渡しになっています。追加の図表は不要です。
