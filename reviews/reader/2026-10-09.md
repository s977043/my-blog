## 1. AI時代に、なぜアジャイルの価値はさらに高まるのか

- URL: https://zenn.dev/minewo/articles/ai-agile-value-increases
- 原稿: `articles/ai-agile-value-increases.md`
- 本文: live（Zenn API `api/articles` の body_html）/ 3,778 文字
- ペルソナ: Z2 設計判断を比べるテックリード（実装手順の記事ではなく、スクラムの実践を見直すかどうかの判断材料を示す記事なので、Z1 より Z2 の方が主題に近い）

### 読むのをやめそうな箇所

- 「## AI時代のスクラムは、実践の形そのものを問い直す」の箇条書き（「これまで通りの1〜2週間のスプリント周期は、本当に最適なのか」など）のあと、「気になることは多くあります。」「まだ、業界全体として確立された答えがあるわけではありません。」と続くところ。問いが並ぶだけで、どれを選ぶかの判断や理由が出てこない。Z2 が「採用理由が書かれず」「適用範囲や限界が書かれていない」ところで読むのをやめる地点に当たる
- 同じ節の後半「ただし、ここで強調したいのは……本質は動かない」から「根本思想そのものは、むしろこれまで以上に重要になるはず」まで。TL;DR、「## アジャイルの本質は……」節、まとめと重なり、読み飛ばされやすい
- 「## これから見直したい論点」の表。「AI時代に考えたいこと」の列は「検討する」「重視する」などの方向だけで、何を基準に選ぶか、どこまで当てはまるかが書かれていない

### 分かりにくい用語

- 「ベロシティ」: 初出は「## AI時代のスクラムは……」の箇条書き。説明はないが想定読者には通じる見込み
- 「リードタイム」: 初出は「## AIは学習サイクルを加速する」の「バグ修正のリードタイム」。何から何までの時間かの定義がないまま表でも指標として出てくる
- 「学習速度」「仮説検証数」: 表のメトリクス行。どう数えるかの説明がない
- 「AIへの指示力」: 表のチームスキル行。何を指す力なのかの説明がない

### 導線

- 冒頭: 「想定読者」「この記事で得られること」「TL;DR」があり、最初の 3 ブロックで何の記事で自分に関係があるかが分かる
- 読後: まとめで終わっていて、次に読むもの（関連記事・参考文献）や試すことは書かれていない。本文に外部リンクもない
- 構成: 見出しだけで主張の流れは追えるが、「スクラムの価値はむしろ高まる」と「まとめ」の役割が近い

### 改善案

| 優先度 | 箇所                                               | 提案                                                                                                                                              | 理由                                                                          |
| ------ | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| P1     | 「## これから見直したい論点」の表                  | 論点ごとに「最初に試すなら」または「判断の目安」を 1 列か 1 文足す。例:「スプリント周期: まず 1 スプリントだけ 1 週間で試し、レビューで評価する」 | 予告された「具体論点」が方向の提示で終わり、Z2 が導入を判断する材料に届かない |
| P2     | 「## AI時代のスクラムは……」の後半の段落            | 「本質は動かない」の再説明を 1〜2 文に縮め、表に早く進むようにする                                                                                | TL;DR・本質の節・まとめと重なる（スマホでの長さは段落数からの推定）           |
| P2     | 表の「リードタイム」「学習速度」「仮説検証数」     | 表の直後に、それぞれ何を数えるかを 1 行ずつ添える                                                                                                 | 指標として挙げているのに定義がなく、採用を判断できない                        |
| P2     | 記事末尾                                           | まとめの後に「参考」または「次に試すこと」を置く。例:「まずレトロで AI 活用を 1 項目だけ振り返ってみる」                                          | 読み終えたあとの行動が示されていない                                          |
| P3     | 表（5 行×3 列で、セルに長めの文がある）            | セルの文を短くするか、論点ごとの箇条書きにする                                                                                                    | スマホでは横にはみ出すか折り返しが多いと推定                                  |
| P3     | 「## スクラムの価値はむしろ高まる」と「## まとめ」 | どちらかにまとめるか、役割の違いが分かる見出しにする                                                                                              | 見出しを拾うと結論の節が 2 つあるように見える                                 |

- 画像 3 点の中身（alt テキストのみ取得）

- コードブロックは原稿・本文ともになし
- 記事末尾に Zenn が出す関連記事などの、本文以外の導線

## 4. AI記事制作で品質を落とさない：編集フローを3層の品質ゲートで設計する

- **Governance / Execution / Improvement**: 英語の層名だけが見出しになっている
- **CTA**: 「## 3. Improvement」の「CTAが一般論だった」で説明なし
- **Growth Lab**: 冒頭のリンクに説明がない

### 導線

- 読後: 「最小構成」のファイル例と「公開前チェックリスト」で試すことは示されている。「## 参考」の Zenn 記事 2 本には本文とのつながりの説明がない

### 改善案

| 優先度 | 箇所                           | 提案                                                                                                        | 理由                                                                                |
| ------ | ------------------------------ | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| P1     | 冒頭 1 文目                    | 「下書き」をやめる。例:「Growth Lab（筆者が運営する記事メディア）の記事制作フローをもとに整理した記事です」 | 公開記事を下書きと呼ぶと比較の段階で候補から外される。Growth Lab が何かも伝えられる |
| P2     | 「## 3層で考える」の表         | DoD と 4視点レビューを初出で補う。例:「DoD（完成の定義）」「4視点レビュー（後述）」                         | 表の段階で意味が取れない                                                            |

| P3     | 「## 参考」の Zenn 記事 2 本   | 1 行ずつ関係を添える                                                                                        | 次に読む理由が分かる                                                                |
| P3     | 「CTAが一般論だった」          | 「CTA（読後に促す行動）」と補う                                                                             | 略語に説明がない                                                                    |
