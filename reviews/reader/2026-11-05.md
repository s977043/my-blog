## 1. 品質ゲートは効かなかったのではなく、「呼ばれたか」を測れていなかった

- URL: https://zenn.dev/minewo/articles/ai-review-gate-not-called
- 原稿: `articles/ai-review-gate-not-called.md`
- 本文: live（zenn api/articles body_html）/ 9363 文字
- ペルソナ: Z2 設計判断を比べるテックリード（主題が手順ではなく、品質ゲートの観測設計と状態遷移の判断のため）

### 読むのをやめそうな箇所

- 冒頭 `:::message`「この記事の規模」: 「Humanizeレビューの実行証跡」「findings は6件」「別の3件は……Git 履歴からのみ追跡」と、何のレビューかを知る前に数値と用語が続く。Z2 は「適用範囲や限界が書かれていない」ではなく前提が掴めない段階で、比較候補から外しうる
- 「## 1か月後に数えたら、8本中2本にしか証跡がなかった」の `git log` 2本: 集計コマンドの再現性は伝わるが、Z2 は設計判断を探しており、コマンドが続く区間で流し読みに変わりやすい（離脱までは至らない程度）
- 「### 工程5が落ちる：識別子が集計キーにならない」: `F01`〜`T15`、`S12-recurring-importance-closer` などの識別子の列挙が続き、自分のチームへの示唆（何を直せばよいか）が「一般化の限度について」まで出てこない

### 分かりにくい用語

- Humanize レビュー（`:::message` で初出）: 「はじめに」第3段落の「検出だけして本文を書き換えない Humanize レビュー」まで定義が無い
- findings（`:::message`「この記事の規模」）: 説明なし。レビュー指摘の意味と推測はできる
- verified / unverified（`:::message`「採否は自由。記録されるまで verified にしない」）: 状態名としての定義は「## 止めるか、止めないかで考えていた」まで出ない
- StructuredOutput（「### 工程5」）: Claude Code / SDK の機能名か一般名詞か分からない
- drift（「### 工程5」）: 説明なし
- eligible / unobserved（「### 次に作る状態遷移」）: 図の中で定義されるが、図を見ない読者（後述）には本文で一言の説明が無い
- left join（「## 次に変える8点」6.）: SQL 用語。Z2 には通じる想定だが、記事の読者層によっては一言あるとよい

### 導線

- 冒頭3段落: `:::message` の「得られること」「想定読者」「扱うもの」で、何の記事かと対象は分かる。ただし主役の Humanize レビューが何かは本文に入るまで分からない
- 構成: 見出しだけで「仮説 → 誤認 → 計測 → 工程ごとの失敗 → 原因 → 次の8点」が追える。「## ゲートは工程ごとに別々に観測不能になる」の表が全体の地図として機能している
- 適用範囲: 「言えること／言えないこと」「一般化の限度について」「チームに持ち込むときの注意」で限界が明示されており、Z2 の判断材料として強い
- 読後: 「次に変える8点」と JSON の初期レコード例で試すことは明確。「## 関連記事」3本に、どれを次に読むかの一言が無い

### 改善案

| 優先度 | 箇所 | 提案 | 理由 |
| --- | --- | --- | --- |
| P1 | 冒頭 `:::message` の先頭 | 1行目に主役を定義する。例:「Humanize レビュー（AI が書いた記事の定型的な文体を検出だけする、本文を書き換えない review-only のレビュー）を1か月運用した記録です。」 | 規模の数値と用語が定義より先に来るため、比較目的の読者が前提を掴めず離脱しうる |
| P2 | `:::message`「この記事の規模」 | findings を「指摘」に言い換えるか、後半へ回して規模は「8本中2本」だけに絞る | 冒頭の情報量が多く、要点の 25% が埋もれる |
| P2 | 「### 工程5」の識別子列挙の直後 | 先に「チームへの示唆」を1文置く。例:「出力例とパターン表が食い違うと、正しく動いても集計できません。」 | 識別子の細部が続き、判断の話に戻るまでが長い |
| P2 | 「### 工程5」StructuredOutput・drift の初出 | 一言の説明を添える。例:「StructuredOutput（スキーマ付きの JSON 出力）」「drift（値の揺れ）」 | 用語で手が止まる |
| P3 | 「## 関連記事」 | 次に読む1本を一言で示す（例: 状態機械の記事は「`verified` 判定を PR 運用に置いた例」） | 3本が並列で選びにくい |
