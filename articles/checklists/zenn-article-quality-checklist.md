# Zenn記事品質チェックリスト

Zenn記事を、技術的に正確で、読者が理解・再現しやすく、将来も逆引きできるストック資産へ近づけるためのチェックリスト。

構成の詳細な判断基準は `articles/guides/zenn-structure-best-practices.md` を正本とする。記事作成前・執筆中・公開前レビューで併用する。

## 必須確認

- [ ] 誰向けの記事か説明できるか？
- [ ] この記事で何が分かる / できるようになるか冒頭で伝わるか？
- [ ] 対象技術・バージョン・環境・発生条件のうち必要なものが明示されているか？
- [ ] タイトルが本文の内容と一致しているか？
- [ ] 技術的な主張を一次情報または実測で確認しているか？
- [ ] 実体験・試行錯誤・独自の判断のいずれかがあるか？

## Front Matter

- [ ] `title` が内容を正確に表しているか？
- [ ] `emoji` が1文字で、記事内容と大きくずれていないか？
- [ ] `type` が `tech` / `idea` の内容に合っているか？
- [ ] `topics` が関連する語に絞られているか？
- [ ] `published` を意図せず変更していないか？

## 冒頭

- [ ] 対象読者が分かるか？
- [ ] 解決する問題 / 得られることが分かるか？
- [ ] 長文の場合、TL;DRまたは同等の先出し結論があるか？
- [ ] 必要なら `:::message` で前提条件を切り出しているか？
- [ ] 既存記事からの再構成なら、検索意図が重複していないか？

## 構成

- [ ] 本文の見出しは原則 `##` から始まっているか？
- [ ] 見出しだけ読んでも論理が追えるか？
- [ ] 詳細に入る前に全体像があるか？
- [ ] 1つのH2に複数の主題を詰め込みすぎていないか？
- [ ] 手順だけでなく、理由・失敗・判断基準があるか？
- [ ] 適用範囲と制約が書かれているか？
- [ ] まとめが本文の繰り返しだけになっていないか？

## 再現性

- [ ] 必要なバージョン・環境が明示されているか？
- [ ] コマンドやコードが実行可能か再確認したか？
- [ ] 期待結果が必要な箇所で示されているか？
- [ ] 一部省略したコードは省略を明記しているか？
- [ ] 失敗時の症状や確認ポイントがあるか？
- [ ] 計測値は計測範囲・基準日・除外条件が分かるか？

## 事実検証

- [ ] API / CLI / ライブラリ仕様は公式ドキュメント・README・CHANGELOGで確認したか？
- [ ] 実装挙動は実コード・テスト・ログで確認したか？
- [ ] 数値は可能なら公開前に再計測したか？
- [ ] 「存在しない」「0件」などの主張で、未観測を確定値として扱っていないか？
- [ ] 古いバージョンの情報を現在の仕様として書いていないか？

## コード・Zenn記法

- [ ] コードブロックに言語指定があるか？
- [ ] 長い設定・ログ・補足は `:::details` に畳む方が読みやすくないか？
- [ ] 重要な前提や制約は `:::message` が適切か？
- [ ] 破壊的操作やセキュリティ注意は `:::message alert` が適切か？
- [ ] 3項目以上の並列比較は表の方が理解しやすくないか？
- [ ] 表のセルに長文を詰め込んでいないか？
- [ ] 画像には必要に応じてAltテキストやキャプションがあるか？

## タイトル・検索意図

- [ ] 対象技術や固有名詞が必要ならタイトル前半にあるか？
- [ ] 問題・目的・発見のどれかが分かるか？
- [ ] `〜してみた` だけで結果が不明なタイトルになっていないか？
- [ ] 本文で証明していない効果を断定していないか？
- [ ] 既存記事と同じ検索意図を奪い合っていないか？

## Zennで価値になる一次情報

- [ ] 実際に試した結果があるか？
- [ ] ハマりどころ / 失敗があるか？
- [ ] 別案との比較があるか？
- [ ] 設計判断と理由があるか？
- [ ] 独自の計測・検証があるか？

すべてを満たす必要はないが、一般知識の再構成だけの記事になっていないことを確認する。

## 終盤

- [ ] 読者が次に試せる具体的な行動があるか？
- [ ] 採用すべき条件 / 採用しない条件が分かるか？
- [ ] 関連記事や公式ドキュメントへの導線が必要か？
- [ ] 今後の未検証事項を、検証済みの事実と混ぜていないか？

## 公開前

- [ ] `npm run check` 等のリポジトリ標準検証を通したか？
- [ ] 可能なら `npx zenn preview` で表示確認したか？
- [ ] リンク切れがないか？
- [ ] `published: true` の記事はrelease/zenn経由の公開フローを守るか？
- [ ] 公開済み記事のslugを変更していないか？

## レビュー時の扱い

- 全項目をレビュー成果物に転記しない
- 技術的正確性・再現性・読者の判断に効く指摘を優先する
- 構成ガイドを固定テンプレートとして機械適用しない
- 記事タイプ（実装 / トラブルシュート / 設計 / Idea）に応じて対象外を認める
