# 依存の大きな更新を、更新前との比較で確かめる。新しく出た問題だけを拾うスモーク E2E

> **企画**: 2026年12月 PRONI公式テックブログ（note 会社公式）候補。2026-11-27 に著者が候補 A として選んだ
> **状態**: 裏取り済み（下記）。Draft Article Plan まで。初稿は未作成
> **位置づけ**: 12月分として保留中の `PRONI-pr-review-order` の代わり。セキュリティ強化 PJ の連載とは重ならない（脆弱性の詳細は書かない）
> **公開境界**: 会社リポジトリの開発実践が題材。PRONI公式の社内レビュー・広報確認を経る。個人記事への転用不可。著者の個人リポジトリ（River Review・PlanGate など）は使わない

## 裏取りの結果（2026-11-27、会社リポジトリの main とマージ済み PR で確認）

社内の値のため、PR 番号・リポジトリ名・チケット番号・社内 URL はここに書かない。

実施済みの改善と結果:

- フロントエンドのビルドツールのメジャー更新（Vite 5 → 8、Vitest 3 → 4。管理画面と公開サイト 4 つ）で、実ブラウザで公開サイトと管理画面を巡回するスモーク E2E を作った
- **更新前の結果を比較元にし、新しく出た問題だけを拾う**判定にした。既知の問題（ハイドレーション警告、横はみ出し）が更新前からあり、比較なしでは毎回失敗になるため
- **このスモークで実際に不具合を見つけた**: 管理画面で、CJS パッケージのアイコンを default import していた箇所が、更新後に保存後のトーストで `Application Error` になった。型チェックと lint では見つからず、実行時にだけ出た。名前付き import に直し、同じ形の import を lint で禁止した
- 判定は数回直した。別ページの既知の問題が新しい問題を隠していたので、比較を同じパスのページ同士に絞った。同じ種類の問題は件数が増えたときだけ新しい問題とした。スモークを回せなかったときも失敗で終えるようにした
- 比較が効いていることも確かめた。比較元のパスをずらすと新しい問題として出た。照合キーから幅の条件を消すと、新しい問題が既知の問題に隠れた（変異テスト）
- 更新後の結果: 全項目 OK、更新前と比べて新しい問題 0 件
- **2回目の利用**: PHP のベースイメージ更新で、本番のリリース前に結果を取り、リリース後に比べて新しい問題が無いことを確かめた。そのとき一時コピーで済ませた手順を、dev / 本番の公開サイトと PC / SP の 2 幅で流せる形に取り込んだ。本番は読み取りだけで、管理画面の送信は止める
- 依存の更新と道具は別の PR に分けた（revert の単位を分けるため。レビューの提案）

うまくいかなかったこと・限界:

- ローカルの dev サーバーの再最適化で接続が切れることがあり、取り直しを入れた
- 既知の問題は残っている。比較元は依存を上げたとき・既知の問題を直したとき・巡回するページが変わったときに取り直す必要がある
- CI には入れていない（ローカルと手動の実行）。定期実行は手順書に書いたが、運用の記録は無い

## 自分の解釈

- 依存の大きな更新は、テストが通っても実行時にだけ壊れることがある。全部を直してから確かめるのではなく、「更新前より悪くなったか」を見れば、既知の問題を抱えたままでも判断できる
- 比較が効いているかは、わざと壊して確かめる
