# 執筆スタイルシート（river-review-guide）

- 敬体を基本にする
- 日本語で責務を説明してから英語ラベルを導入する
- 成功談だけでなくIssue / PR / fixture / limitationを一次情報として使う
- Experimental / PlannedをImplementedとして書かない
- Review Judgment as Code = 中核思想
- Review Judgment Platform / team-owned audit layer = 現在の位置づけ
- Engineering Judgment Infrastructure = 長期方向であり現在機能の呼称にしない
- Verdictは判断材料であり、承認・merge権限そのものではない

## Evidence Boundary

- Observed: Issue / PR / 実行ログなどの観測
- Verified: current mainのコード・schema・公開docsで確認した仕様
- Interpretation: 設計意図や一般化
