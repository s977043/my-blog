# PlanGateは「Plugin」よりGovernance Harnessとして見る

> Draft. 配布形態ではなく、PlanGateがどの責務を組み合わせているかを整理する。

## Pluginだけでは説明できない

Claude Code / Codexへ導入する入口はPluginでも、設計対象はPlugin APIそのものではありません。

## Harnessとは何を設計するのか

## Workflow: 仕事の順序

## Skill: 再利用可能な能力と判断手順

## Agent: 役割を持つ実行者

## Gate: 次へ進んでよい条件

## Artifact: 状態と判断材料の正本

## Hook: 境界を機械的に強制する層

## 自律性ではなく境界を設計する

この分類は役割を分けるためのPlanGate側の設計整理であり、業界共通の分類として一般化しない。
