# AgentではなくArtifactを信頼する

前章では、AIの「規模M」という判断をそのまま採用せず、実際のファイル数を数えたことで判断を変えられた事例を紹介しました。

ここで重要だったのは、どちらのAIを使ったかではありません。

**AIの説明の外側に、確認できる事実があったこと**です。

この章では、その考えをもう少し一般化します。

## 「完了しました」を、そのまま完了にしない

AIエージェントへ長い仕事を任せていると、次のような報告を受け取ります。

- 実装しました
- テストは通っています
- 問題ありません
- PRを作成しました
- 完了です

これらは便利な要約です。

ただし、要約そのものは証拠ではありません。

「テストは通っています」と言われたなら、確認したいのはテスト結果です。「要件を満たしています」と言われたなら、確認したいのは受入基準と、その基準に対応する検証結果です。

AIの自己申告を疑って毎回すべてを人間がやり直す、という話でもありません。

必要なのは、判断の入口を変えることです。

```text
Agentの説明
    ↓
そのまま判断
```

ではなく、

```text
Agent
  ↓
Artifact
  ↓
Evidence
  ↓
Judgment
```

という形にします。

## Artifactは「状態を外に出したもの」

ここでいうArtifactは、AIとの会話の外に残る成果物です。

PlanGateでは、たとえば次のようなものがあります。

- RequirementやPBIの入力
- `plan.md`
- `todo.md`
- `test-cases.md`
- Review結果
- `status.md`
- handoff
- 実装されたコード
- PR
- 検証結果

重要なのは、ファイル形式がMarkdownかどうかではありません。

**次の人や次のAgentが、会話履歴を全部知らなくても状態を確認できること**が大切です。

会話だけに状態があると、「どこまで決まったか」「何が承認されたか」「どの前提が未確認か」がセッションの流れに埋もれます。

Artifactへ出すと、その状態を別の主体が読み直せます。

## Evidenceは「その主張を支えるもの」

ArtifactとEvidenceは同じではありません。

たとえば、`plan.md`が存在することはArtifactです。

しかし、そのPlanに「対象ファイルは20件」と書いてあったとしても、20件である根拠がなければ、その数字を信頼する理由はありません。

そこで必要になるのがEvidenceです。

```text
Claim:
「対象は20ファイル」

Evidence:
find / grep / repository search の結果
```

あるいは、

```text
Claim:
「Acceptance Criteriaを満たした」

Evidence:
ACと対応づいたtest result
```

です。

この区別は地味ですが、かなり重要です。

**Artifactがあることと、そのArtifactの内容が正しいことは別**だからです。

## 成果物を信頼する、とは無条件に信じることではない

「AgentではなくArtifactを信頼する」と言うと、Artifactさえあれば安全だと聞こえるかもしれません。

そうではありません。

PlanGate自身でも、「ファイルがある」「検査がgreenになった」という事実だけでは不十分だったケースが何度もありました。後の章で詳しく扱いますが、pluginが実際には読み込まれていないのにdoctorが `registered: YES` を返していたこともあります。

つまり、

> **存在しているArtifactではなく、判断したい主張に対応したEvidenceを見る**

必要があります。

Artifactは、判断材料を置く器です。

Evidenceは、その中の主張を外から確かめる材料です。

Judgmentは、それらを見て次へ進むか決める行為です。

この3つを分けると、「AIがそう言ったから」から少し離れられます。

## 人間が全部確認するための仕組みではない

ここでもう一つ誤解しやすい点があります。

ArtifactとEvidenceを増やす目的は、人間が毎回すべてのログを読むためではありません。

むしろ逆です。

人間が見る必要があるのは、重要な判断に必要な材料です。

たとえば、

- 何を作る計画なのか
- どこまでが承認範囲なのか
- 受入基準を満たした証拠があるか
- 未解決のリスクが残っているか

が短く確認できればよい。

そのためには、Agentの会話履歴を読むより、判断に必要なArtifactとEvidenceが整理されている方が扱いやすくなります。

## この章で持ち帰ること

AIエージェントを信頼するか、信頼しないかという二択にする必要はありません。

設計対象を、Agentの性格や自己申告から、外から確認できるArtifactとEvidenceへ移します。

ただし、Evidenceが揃っても最後の問いが残ります。

「テストが通った」と「この変更を採用してよい」は同じでしょうか。

次章では、ここを **Verification / Review / Judgment** の3つに分けます。
