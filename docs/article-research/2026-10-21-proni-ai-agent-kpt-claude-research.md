# Claude Code調査ブリーフ：アジャイルの振り返りをAI駆動開発に取り入れた実践

- 作成日: 2026-10-21
- 用途: 2026年11月のPRONI公式テックブログ記事の一次情報収集
- 対応Seed: `article_seeds/ai-driven-development/2026-10-21-ai-agent-kpt-retrospective.md`
- **目的**: 記事執筆ではなく、実際に行った活動とその根拠の調査

## Claude Codeへの依頼

以下をClaude Codeの実運用環境で調査すること。記事本文はまだ作成しない。

### 背景

著者はAI駆動開発に、アジャイル開発で培ったチケット分割、タスクごとの計画、レビュー、短いフィードバックの考え方を取り入れてきた。主な実行環境はClaude Codeで、実際のSkillとWorkflowはGTAで管理している。

AIエージェント自身に開発の出来事をKeep / Problem / Tryで報告させ、人間と壁打ちして改善を選ぶことを記事化したい。セッション単位、週次、約60日の期間集計という複数の振り返りがあるとの著者説明を、実運用の記録で確かめる。

「AI駆動開発はプチウォーターフォールが適しているように感じる一方、アジャイルのエッセンスを積極的に使っている」という問題意識も扱う。両者を二項対立として断定しない。

### 最初に対象を特定

1. 現在のワークスペースを確認する。GTAの正式名称・GitHub管理先・ローカルパス・運用スキルの正本を調べる。
2. `AGENTS.md`、`CLAUDE.md`、README、Skill / Workflow / Agentを確認する。
3. `retrospective-improvement`、`engineering-process-improvement`、`retrospective-analyst`、`06_retro` は**候補語**として検索する。定義の存在と実使用を分ける。
4. 直近60日間を原則とし、導入経緯が必要な場合に限り過去へ遡る。調査期間を報告する。

### 具体的な調査

**A. アジャイル開発の取り込み**
- 要求整理、設計、巨大チケット分割、タスク単位の計画、レビュー、実行、検証、適応に対応する実運用
- それぞれのSkill / Workflowの責務、変更履歴、運用証跡

**B. 3つの振り返り**
- セッション: 終了時の出来事、KPT、Try、AIと人間の会話・判断、実装改善
- 週次: 1週間の複数セッション横断、前回Tryの効果、繰り返しの検知
- 約60日: PRレビュー指摘の横断集約、傾向、Skill / Workflowの改善判断と効果
- 実施済み / 部分実施 / 設計のみ / 構想を明確に区別する

**C. KPTの実例を3〜5件**
- 特にPR指摘から改善したもの、前回Tryが効果を示したもの、改善したが再発したものを優先
- 各例: 背景、実際の出来事、Keep / Problem / Try、AI提案、人間判断、変更内容、検証状況、証拠URL
- 実際の会話ログがなければ会話を捏造しない

**D. PRの繰り返し指摘とSkill改善**
- 設計整合性、計画不備、受入条件不足、テスト漏れ、スコープ外変更、完了誤報など
- `PRレビュー指摘 → KPT → Try → 採用判断 → Skill/Workflow変更 → 次回検証` の時系列チェーンを追跡
- 途中の証跡がなければそこで未確認とする
- 改善による複雑化やコスト増、ルール増殖も考慮する

**E. 記事の結論の検証**
- AIと振り返ると、何が見えるようになったか
- 人間が判断すべき境界はどこか
- AIが出す事実と原因仮説はどう区別されているか
- 証明できる実践と、著者の考察として書くべき部分は何か

### Evidenceルール

- 一次情報はPR・Issue・コミット・差分・レトロログ・CI検証・Skill変更・参照可能なClaude Codeセッションログ
- 「スキルが存在する」「呼ばれた」「効果があった」はそれぞれ異なる
- 人間が承認した事実とAIが提案した事実を混同しない
- 指摘→修正の時系列を確認し、改善の因果関係を作らない
- 実績や改善率を根拠なく主張しない
- 会社の運用と個人OSSでの事例を混ぜない
- 社外公開前提のため、機密情報・認証情報・個人情報は出力しない。社内限定の参照は公開要確認とする
- 引用できるURL・パス・コミットSHA・必要なら行番号を示す

### 出力フォーマット

1. **要約**：確かめられた事実、重要な発見、未検証
2. **開発フロー地図**：役割とSkill / Workflow、設計と実運用の差
3. **振り返りの実施状況**：セッション・週次・60日で比較
4. **KPT事例**：Keep / Problem / Try / AI提案 / 人間判断 / 実改善 / 検証結果 / Evidence
5. **PR指摘→改善トレース**：具体的な変更前後とその証拠
6. **成功・失敗・未評価**：誇張せず分類
7. **社外記事で使える有力事例3件**：根拠と公開リスク
8. **記事構成案**：導入（プチウォーターフォールの違和感）からアジャイル、KPT、時間軸、スキル改善、学びへ
9. **著者に確認が必要な点**：最大5項目

### 実行制約と受け渡し

- 基本は読み取り調査。対象リポジトリの既存ファイル、Skill、Workflowを変更しない。
- コミット、PR作成、マージ、機密情報の外部送信は行わない。
- 結果はClaude Codeのセッションに全文報告し、**レポート1件の保存のみ別途ユーザーから許可があれば** `docs/research/2026-10-21-ai-agile-retrospective.md` 等へMarkdownで保存する。
- 保存した場合は絶対パスと要約を返す。ChatGPTへの引き継ぎはMarkdownファイルのアップロード、またはGitHubの実在するURLを用いる。
- 判断は「確認できた実践」「実践から導ける考察」「まだ確認できないこと」を必ず分ける。
