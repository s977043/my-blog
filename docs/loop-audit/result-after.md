## サマリ

- **B:2 / C:4 → B:4 / C:2。**
- 上がった 2 軸は、どちらも Before の診断で特定した共通原因（「次に何をやるか決める仕組み」「異常を申告する仕組み」の欠落）に直接対応する。
- **A に届かなかった理由も 2 軸で共通している**: どちらも「機械が状態を*書く*ようにはなったが、状態を*読んで動く*ようにはなっていない」。次の一手はここ。

## 実装中に判明したこと（設計時に想定していなかった）

- 仕事の発見を自動化した最初の実行で **34 件**の候補が出た。34 件の backlog は 0 件と実質同じで、人間が読まない。
- 「起票できること」と「起票すべきこと」は別問題だった。シグナルの強さでスコアを付け、`ADOPT_SCORE=3` 未満を捨て、1 回の起票を `ADOPT_LIMIT=5` 件に制限して 34 → 15（スコア足切り後）→ 5（`ADOPT_LIMIT=5`）に収束させた。
- **自動化は人間の作業を消すのではなく、人間が判断する対象の総量を決める仕事に置き換える。** 足切り基準を持たない自動化は、判断コストを人間に転嫁するだけで総量を増やす。
