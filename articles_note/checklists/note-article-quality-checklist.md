# note記事品質チェックリスト

note記事を「書いたもの」から、読者の悩みに届き、クリックされ、最後まで読まれ、保存・購入・信頼につながるコンテンツへ近づけるためのチェックリスト。

記事作成前、執筆中、公開前レビューで使用する。すべてを満たすことが目的ではなく、記事の目的・読者・公開状態に照らして、弱い箇所を見つけるために使う。

元情報は Issue #209 の本文を初版の正とする。元画像は Issue に未添付で、画像下部に不足がある可能性があるため、必要に応じて後続で補完する。

構成の詳細な判断基準は `articles_note/guides/note-structure-best-practices.md` を正本とする。note記事の新規作成・構成レビューでは、このチェックリストと合わせて必ず参照する。

## 使い方

まず「必須確認」だけを見て、記事の方向がズレていないかを確認する。時間がある場合や公開前レビューでは、後続の詳細チェックを使って弱い箇所を探す。

有料記事・販売導線がある記事では、価格、無料パート、CTA、信頼性の項目まで確認する。無料記事や記録・体験・考察系の記事では、該当しない項目を無理に満たそうとしない。

## 使うタイミング

- 記事作成前: テーマ、読者、読後に残したい理解・判断・行動を確認する
- 執筆中: 本文構成、余白、具体性を確認する
- 公開前レビュー: タイトル、リード、読者体験、必要な記事ではCTAを確認する

## 必須確認

- [ ] 誰の、どの悩み・問いに向けた記事か一文で説明できるか？
- [ ] テーマ、タイトル、リード、読後ゴールが同じ読者像に向いているか？
- [ ] 冒頭で、読む理由と何を持ち帰れるかが伝わるか？
- [ ] 本文に、具体的な体験・根拠・例のいずれかがあるか？
- [ ] 読後に「理解・判断・行動」のどれを残したいか説明できるか？

## note構成ベストプラクティス

詳細は `articles_note/guides/note-structure-best-practices.md` を参照する。特に長文の技術・組織・体験記事では、**記事タイプに該当する項目だけ**を優先確認する。

- [ ] スマホ1画面程度で、問題・対象読者・持ち帰りが分かるか？
- [ ] 必要に応じて「先に結論」を置き、価値を詳細説明より前に出しているか？
- [ ] 長文では、見出しだけを追っても主要な論理やストーリーが分かるか？
- [ ] `Phase 1` や `概要` のような管理ラベルだけでなく、必要に応じて読者にとっての発見・変化を見出しにしているか？
- [ ] 体験・導入記事では、実体験が「やったこと → 失敗/限界（存在する場合） → 学び → 必要に応じた一般化」まで進んでいるか？
- [ ] ツール/サービス記事では、固有名詞の説明が読者にも起こる問題より前に出すぎていないか？
- [ ] 記事タイプに応じて、判断基準・原則・問いなど読後に再利用できるものがあるか？
- [ ] ケース/ツール記事では、必要に応じて固有事例から別の環境でも使える言葉へ一般化できているか？
- [ ] 長文では、図・引用・箇条書きなどの視覚的な区切りが必要か？
- [ ] note公開時に目次をONにする必要がある長さか？

## 構成案・セルフレビュー

構成案を作った段階と、本文を書き終えた段階の両方で確認する。

### 構成案

- [ ] この記事の中心の問いを一文で説明できるか？
- [ ] H2だけを上から読んで、読者が追うストーリーが分かるか？
- [ ] H2が論点の目録にならず、前の章から次の章へ理解が進む構造になっているか？
- [ ] 並列の具体テーマを、より上位の意味で1つのH2に束ねてH3へ下げられないか？
- [ ] 各H2の役割が重複していないか？
- [ ] 終盤に「まとめ」「次の仮説」「別記事の予告」など複数の閉じが競合していないか？
- [ ] H2の本数ではなく、読者が同時に追う思考軸の数を減らせているか？

### 専門用語の密度

- [ ] 対象読者が知らない可能性のある専門語は、初出で短く意味を説明しているか？
- [ ] 同じ専門語の括弧説明を2回目以降も繰り返していないか？
- [ ] 英語名詞が1文や1段落に連続し、意味を推測しないと読めない箇所がないか？
- [ ] 一覧・分類では、正式名称を残しつつ一言で役割が分かるか？
- [ ] 用語集セクションを増やすより、本文中の初出説明で解決できないか？
- [ ] 固有ツール名や独自概念が、読者の問題を理解する前に出ていないか？

### 削るレビュー

- [ ] 同じ主張を導入・中盤・結論で必要以上に繰り返していないか？
- [ ] 同じ図やLoopを複数回出していないか？
- [ ] すでに説明した用語を再説明していないか？
- [ ] 独立H2にする必要のない具体例をH3や本文へ畳めないか？
- [ ] 終盤の次テーマが、現在の記事の結論より目立っていないか？
- [ ] 内容・事実確認のあとに、追加ではなく削除だけを目的にしたPassを1回行ったか？

## テーマ設計

- [ ] 普遍的な悩みに基づいたテーマか？
- [ ] 読者の理想像に訴求しているか？
- [ ] 一時的な流行や炎上に頼っていないか？
- [ ] 書き手の専門性と連動したテーマか？
- [ ] 過去の自分に届けたい内容になっているか？
- [ ] ターゲット層の検索意図を想定しているか？
- [ ] テーマに一貫性があるか？
- [ ] 需要のあるジャンルに属しているか？
- [ ] SNSと親和性が高いか？
- [ ] 時間が経っても読まれるテーマか？

## サムネ・タイトル設計

- [ ] 読者の課題を明示しているか？
- [ ] クリックしたくなる表現になっているか？
- [ ] サムネとタイトルで内容を補完しあえているか？
- [ ] バズ狙いの釣りタイトルではないか？
- [ ] SEOキーワードが含まれているか？
- [ ] 読後の変化が想像できるか？
- [ ] コンテンツの中身と一致しているか？
- [ ] 数字や具体例が含まれているか？
- [ ] 共感・痛み・未来などを感じるか？
- [ ] 競合と被っていないか？

## 本文構成

- [ ] 初見で内容が想像できるか？
- [ ] 導入で共感または問題提起をしているか？
- [ ] 誰に向けた記事か明確か？
- [ ] 自己紹介から入っていないか？
- [ ] その記事で満たせるニーズと満たせないものを提示しているか？
- [ ] 中盤で具体的な体験やロジックがあるか？
- [ ] 結論がしっかりと提示されているか？
- [ ] 目次またはセクション分けがあるか？
- [ ] 長すぎず、短すぎないか？
- [ ] 例え話や図解の補助があるか？
- [ ] 文章が論理的につながっているか？
- [ ] 見出しごとに意図があるか？
- [ ] 見出しが並列の論点一覧になっていないか？
- [ ] まとめや振り返りがあるか？
- [ ] スマホでも読みやすい構成か？
- [ ] 冒頭に更新情報を入れる必要があるか？
- [ ] 記事によって生まれた権威を提示しているか？
- [ ] 第三者の口コミを分類して提示できているか？
- [ ] 記事の信頼性・価格の妥当性を論理的に解説しているか？
- [ ] CTAが必要な記事では、記事の目的と読者の状態に合っているか？

## 余白設計

- [ ] 全部説明して安心しているだけになっていないか？
- [ ] 読者が自分事として考えられる問いが入っているか？
- [ ] 体験談を「全部言われたオチまで」書いていないか？
- [ ] 最後を説明だけで締めていないか？

## 読者体験

- [ ] 導入に、読者の頭の中にズレを作る問いがあるか？
- [ ] 抽象的すぎてよく分からないものになっていないか？
- [ ] リリース時点から全力の状態で出しているか？
- [ ] 読者の「今の悩み」が問いで提示されているか？
- [ ] 読んで得られるベネフィットが明確か？
- [ ] 無料パートだけで「良い話だったな」で終わりそうになっていないか？
- [ ] 無料パートは論理と感情の両立ができているか？
- [ ] 読後に新たな視点を得られるか？
- [ ] 感情が動かされる構成か？
- [ ] 書き手の人間性が伝わるか？
- [ ] 最後まで読まれる工夫があるか？
- [ ] 「保存したい」と思える内容か？
- [ ] 学習体験が上がるコンテンツを用意できているか？

## 公開前の最終確認

- [ ] テーマ、タイトル、リード、読後ゴールが同じ読者像に向いているか？
- [ ] 記事の価値が冒頭で伝わるか？
- [ ] 読後に残したい理解・判断・行動が本文と結論に反映されているか？
- [ ] CTAが必要な記事では、次の行動が明確か？
- [ ] noteの公開状態に応じた運用制約を満たしているか？

## レビュー時の扱い

- レビュー成果物では、全項目を転記しない
- 指摘は、読者体験・信頼性・読後価値に効くものへ絞る
- 記事の目的に合わない項目は「対象外」として扱ってよい
- 判断に迷う項目は、本文の修正ではなくレビューコメントやPR本文の保留事項に回す
