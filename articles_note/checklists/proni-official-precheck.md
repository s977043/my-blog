# PRONI 公式テックブログ 提出前チェックリスト

会社公式（PRONI）の note 記事（`articles_note/new/PRONI-*.md`）を、広報の「外部公開資料や取材の事前確認依頼」ワークフローへ出す前に自分で点検するためのチェックリスト。

- 公開可否を最終判断するのは広報。このリストは差し戻しを減らすための事前点検で、広報の判断を置き換えない
- 観点は、広報の AI 自動チェック（2026-10-15 の PlanGate 記事で返ってきたレポート）の 5 カテゴリと、Notion「テックブログ投稿レギュレーション」に合わせている。どちらかが更新されたら、このファイルを追従させる
- 実行は `proni-official-precheck` スキル（`.claude/skills/proni-official-precheck/SKILL.md`）

## 0. 記事タイプの判定

広報チェックはまず記事タイプを判定する。提出前に自分でも 1 行で書いておく。

- 例: 「ハウツー型（AI 開発プロセスのノウハウ解説）＋自社主語型（PRONI プロダクト開発部の内部 AI 活用経験を自社視点で共有）」
- 自社主語型の場合、「なぜ自社の内部事情を公開するのか」が本文から読み取れるか

## 1. 中立性・ステークホルダー配慮

- [ ] 特定のベンダー・パートナー・競合への批判や否定がない
- [ ] ツール名（Claude Code、Codex など）は「使った道具」として中立に書いている。優劣の比較になっていない
- [ ] 「圧倒的に優れている」「唯一の」「必ず」など、根拠のない断定表現がない

## 2. IR・ガバナンス・セキュリティ

- [ ] 未公表の業績・業績予測・M&A・資本政策に触れていない
- [ ] 内部の運用数値（件数、合格率、利用回数など）は、IR 上の意味を持たない業務指標に留めている
- [ ] 社内システムの構成・認証情報・脆弱性・内部 URL・チャンネル名など、セキュリティ上の手がかりを出していない
- [ ] 要注意キーワード（業績、売上、利益、上場、買収、提携予定、未発表 など）を本文で検索し、該当があれば意図を確認した

## 3. 事例の主語と匿名化

- [ ] 主語が「自社（PRONI）」か「著者個人」かが明確で、混ざっていない
- [ ] 著者は PRONI 社員として明示されている（名前 / アカウント）
- [ ] 他社・顧客・パートナー・社外の第三者の実名や、特定できる情報が出ていない
- [ ] 社内メンバーの実名を出す場合は本人の了承がある

## 4. データの信頼性・著作権

- [ ] 数値には前提条件と限界（期間、母数、計測方法、「体感ベース」など）が書かれている
- [ ] 「数倍」「大幅に」などの曖昧な量の表現が、データの限界を書いた文脈の中にある。そうなっていれば判定は「問題なし」で、広報へのメモ候補に挙げるだけにする（具体化は任意。2026-10-15 の広報チェックも同じ扱い）。限界の説明がないまま使っている場合だけ「要確認」
- [ ] 外部の引用・参照に、著者名・日付・リンクが付いている
- [ ] 社内レビュー用の Google ドキュメントでも、外部リンクがハイパーリンクとして残っている（プレーンテキストではリンクの有無を確かめられないため、広報チェックで確認を求められる）
- [ ] 他者の図・画像・文章を転載していない。転載する場合は許諾と出典がある

## 5. ビジネスモデル整合性

- [ ] 内容が自社の内部開発プロセスに限られているか、顧客向け機能・営業プロセスに触れる場合はその記述が正確か
- [ ] 発注側・受注側（出稿パートナー）の関係性に触れる場合、どちらかを下げる・排除する表現がない
- [ ] 出稿パートナーや顧客が読んでも、不快感や不信感を覚える要素がない

## 6. レギュレーション（Notion「テックブログ投稿レギュレーション」）

- [ ] エンジニアレビュー: 部長・副部長 1 名以上と、所属グループ内 1 名以上の承認がある
- [ ] note 執筆ガイドラインを適用した（JTF スタイル、`articles_note/checklists/note-article-quality-checklist.md`）
- [ ] 時制（です・ます／でした・ました）がそろっている（`npm run check:article-sentence-style`）
- [ ] カバー画像はデザイン室のテンプレートから作り、フォントを変えていない
- [ ] AI 生成画像に、文字列・PRONI ロゴに似たもの・ペンギンが入っていない
- [ ] 末尾に公式テックブログ共通の採用告知（【PR】エンジニアの積極採用を実施中です）がある
- [ ] Google ドキュメントに広報（中山さん・哲さん）の編集権限がある

## 提出後

広報の AI 自動チェックは、テスト運用中は参考扱いになる。広報担当の返信を確認してから、修正や公開に進む。
